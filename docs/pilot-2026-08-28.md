# Sanity check: does the index-vocabulary gap survive contact with a real agent?

Corpus: Backlog.md's real, unedited AGENTS.md/CONTRIBUTING.md/DEVELOPMENT.md/
ADVANCED-CONFIG.md/CLI-INSTRUCTIONS.md (5 real docs, 680 lines).
17 questions, written from real facts, locked before either index was built.

## BM25 (nocontext's current scorer)

| index | P@1 | MRR |
|---|---|---|
| as-is (real README link text) | 18% | 0.18 — below the 20% random floor |
| retrieval-rewritten | 71% | 0.79 — at the ceiling |

Confirms Claim A on a real corpus. Large, real gap.

## Claude (general-purpose subagent, Read+Bash, same corpus, same questions)

| index | grounded |
|---|---|
| as-is | 17/17 |
| retrieval-rewritten | 17/17 |

**No difference.** The agent read the index, then opened documents freely
regardless of how well the index's wording matched the question, and got every
answer right under both conditions.

## What this means

The corpus here is 5 files, under 400 lines each. A real agent with tool
access does not need the index to work hard: it costs almost nothing to open
a candidate file, check, and open another if wrong. The index-vocabulary
effect is real under BM25 and invisible to an agent that can cheaply explore.

This does not kill the project. It sharpens what has to be true for it to
matter:

- The effect should reappear once the corpus is large enough that opening
  every candidate is expensive — many files, long files, or a budget/latency
  constraint on the agent.
- The effect should reappear for retrieval mechanisms that are actually
  lexical or embedding-based rather than an agent with unrestricted file
  access — vector search over a wiki, an MCP resource picker, anything that
  ranks rather than lets the agent freely browse.
- Small corpora that fit comfortably in an agent's exploration budget are
  close to a null result for THIS failure mode, regardless of index quality.

Phase 4 cannot pick a repo like this one. It needs corpora large enough, or
constrained enough, that free exploration is not a free out. That is now a
recorded requirement, not a nice-to-have.
